= Code Snippets and Auto-Completion
:experimental:

The Semantic Models extension provides intelligent code completion, pre-built snippet templates, and context-aware value suggestions for authoring SAMM Aspect Models in Turtle (`.ttl`). These features help you write models faster, reduce syntax errors, and explore SAMM constructs effortlessly without memorizing complex syntax.

== How It Works

Completion suggestions appear automatically as you type, or can be triggered manually at any position by pressing kbd:[Ctrl+Space] (or kbd:[Cmd+Space] on macOS).

* *Context-Aware Filtering:* The editor understands where your cursor is positioned—whether you are in the document header, defining a top-level element, adding metadata predicates inside a subject, editing the `samm:properties` list, or declaring an inline characteristic. Only valid and applicable templates are shown.
* *Automatic Prefix & Version Adaptation:* Snippets dynamically resolve and adapt to the prefixes declared in your document (such as `:`, `samm:`, `samm-c:`, `samm-e:`, `unit:`, `xsd:`) as well as the active SAMM metamodel version.
* *Placeholder Navigation:* Press kbd:[Tab] to navigate sequentially between placeholder fields (e.g., element names, descriptions, data types) and kbd:[Shift+Tab] to jump back to previous placeholders.
* *Choice Dropdowns:* Where applicable, placeholders present a dropdown list of valid choices (such as primitive XSD types).

'''

== 1. Document Setup

When creating a new Aspect Model file, generate standard namespace prefixes in a single step:

[cols="20%,30%,50%",options="header"]
|===
| Trigger Prefix | Template Name | Description
| `prefix` / `@prefix`
| SAMM Prefix Header
| Inserts standard `@prefix` declarations for the local model URN, SAMM meta-model, characteristics, entities, units, RDF syntax (`rdf:`), and XML Schema Datatypes (`xsd:`).
|===

.Example Result
[source,turtle]
----
@prefix : <urn:samm:com.example.namespace:1.0.0#> .
@prefix samm: <urn:samm:org.eclipse.esmf.samm:meta-model:2.3.0#> .
@prefix samm-c: <urn:samm:org.eclipse.esmf.samm:characteristic:2.3.0#> .
@prefix samm-e: <urn:samm:org.eclipse.esmf.samm:entity:2.3.0#> .
@prefix unit: <urn:samm:org.eclipse.esmf.samm:unit:2.3.0#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
----

'''

== 2. Core Metamodel Elements

Core metamodel elements define the primary structure of an Aspect Model. You can invoke these templates at the root level of your Turtle document.

=== Top-Level Definitions

[cols="22%,28%,50%",options="header"]
|===
| Trigger Prefix | Template Name | Description
| `Aspect`
| SAMM Aspect
| Root Aspect definition with preferred name, description, properties, operations, and events.
| `property`
| SAMM Property
| Top-level property referencing a characteristic.
| `AbstractProperty`
| SAMM AbstractProperty
| Abstract property definition intended to be implemented or extended by concrete properties.
| `Entity`
| SAMM Entity
| Structured entity containing a list of properties.
| `AbstractEntity`
| SAMM AbstractEntity
| Abstract entity definition intended for specialization.
| `Operation`
| SAMM Operation
| Operation definition with input parameters and return type.
| `Event`
| SAMM Event
| Event declaration with parameters.
| `Value`
| SAMM Value
| Named constant value instance (e.g., for use in `samm-c:Enumeration` or `samm-c:State` value lists).
|===

=== Property Modifiers & Inline Properties

When editing the `samm:properties ( ... )` list inside an Aspect or Entity, type `[` followed by the trigger keyword (e.g., `[optional`) to insert an inline blank-node property configuration:

[cols="22%,28%,50%",options="header"]
|===
| Trigger Prefix | Template Name | Description
| `[optional`
| SAMM Optional Property
| Marks a property as optional: `[ samm:property :propertyName ; samm:optional true ]`.
| `[payloadName`
| SAMM Property with Payload Name
| Specifies a custom JSON/serialized name: `[ samm:property :propertyName ; samm:payloadName "payloadKey" ]`.
| `[notInPayload`
| SAMM Property Not In Payload
| Excludes an Entity or AbstractEntity property from the payload: `[ samm:property :propertyName ; samm:notInPayload true ]`.
| `[extends`
| SAMM Extended AbstractProperty
| Specializes an inherited abstract property in an extending entity (requires `samm:extends` on the enclosing entity): `[ samm:extends :abstractProperty ; samm:characteristic :CharacteristicName ]`.
|===

'''

== 3. Characteristic Types

Characteristics specify the data type, structure, and constraints of properties. The language server provides snippets both as **standalone top-level definitions** and as **anonymous inline blank nodes** (`[ a samm-c:... ]`).

TIP: To insert an anonymous inline characteristic at a characteristic object position (such as `samm:characteristic`, `samm-c:elementCharacteristic`, `samm-c:baseCharacteristic`, `samm-c:left`, or `samm-c:right`), type `[` followed by the characteristic name (e.g., `[Characteristic` or `[Measurement`).

== 4. Constraint Types

Constraints define validation rules and restrictions on characteristics. They can be declared as standalone top-level elements or as anonymous inline blank nodes under `samm-c:constraint`:

[cols="22%,28%,25%,25%",options="header"]
|===
| Trigger | Standalone Template | Inline Template | Description
| `RangeConstraint`
| SAMM RangeConstraint
| SAMM Anonymous RangeConstraint
| Numeric or chronological boundaries (`minValue`, `maxValue`, `lowerBoundDefinition`, `upperBoundDefinition`).
| `LengthConstraint`
| SAMM LengthConstraint
| SAMM Anonymous LengthConstraint
| Minimum and maximum string length or collection cardinality.
| `RegularExpressionConstraint`
| SAMM RegularExpressionConstraint
| SAMM Anonymous RegularExpressionConstraint
| Pattern matching restriction using a regular expression (`samm:value "^[A-Z0-9]+$"`).
| `EncodingConstraint`
| SAMM EncodingConstraint
| SAMM Anonymous EncodingConstraint
| Character set encoding limitation (e.g., `samm:UTF-8`, `samm:US-ASCII`).
| `LanguageConstraint`
| SAMM LanguageConstraint
| SAMM Anonymous LanguageConstraint
| Permitted natural language code formatted according to ISO 639-1.
| `LocaleConstraint`
| SAMM LocaleConstraint
| SAMM Anonymous LocaleConstraint
| Permitted regional locale code formatted according to BCP 47.
| `FixedPointConstraint`
| SAMM FixedPointConstraint
| SAMM Anonymous FixedPointConstraint
| Fixed-point decimal number restrictions specifying integer digits and scale.
|===

TIP: When editing the object of `samm-c:constraint`, type `[` followed by the constraint name (e.g., `samm-c:constraint [RangeConstraint`) to insert the anonymous inline constraint `[ a samm-c:... ]` block with all required fields.

'''

== 5. Metadata & Documentation Predicates

When the cursor is positioned inside a SAMM element declaration, invoking completion on an empty line (kbd:[Ctrl+Space]) or typing with the `samm:` prefix offers quick metadata predicate snippets:

[cols="25%,25%,50%",options="header"]
|===
| Trigger Prefix | Template Name | Generated Code
| `samm:preferredName`
| SAMM preferredName
| `samm:preferredName "${1}"@en ;`
| `samm:description`
| SAMM description
| `samm:description "${1}"@en ;`
| `samm:see`
| SAMM see
| `samm:see <${1:https://example.com/term/}> ;`
| `samm:exampleValue`
| SAMM exampleValue
| `samm:exampleValue "${1}" ;` _(available inside `samm:Property` definitions)_
|===

NOTE: The completion service automatically adapts the trailing statement separator (`;` or `.`) to the surrounding Turtle syntax and tracks existing predicates on the active subject—predicates that are already defined and do not permit multiple occurrences are excluded from suggestion lists.

'''

== 6. Smart Attribute Value Suggestions

In addition to full code snippets, the extension provides context-aware value completions when editing predicate values:

* **Data Types (`samm:dataType`):** Suggests standard XSD types (`xsd:string`, `xsd:integer`, `xsd:boolean`, `xsd:decimal`, `xsd:dateTime`, etc.), predefined SAMM entities (`samm-e:FileResource`, `samm-e:TimeSeriesEntity`), and custom entities defined in your workspace.
* **Measurement Units (`samm-c:unit`, `samm:referenceUnit`):** Search and auto-complete for more than 1,000 standard physical units from the SAMM unit catalog. When editing a `Duration`, time-related units (seconds, minutes, hours, days, etc.) are automatically prioritized.
* **MIME Types (`samm-e:mimeType`):** Quick completion for standard MIME types (e.g., `application/json`, `text/turtle`, `application/pdf`, `image/png`, `model/step`) with human-readable format descriptions.
* **Languages & Locales (`samm-c:languageCode`, `samm-c:localeCode`):** Full list of ISO 639-1 language codes (with common languages like `en`, `de`, `fr`, `es` prioritized) and standard BCP 47 locales (`en-US`, `de-DE`, etc.).
* **Bounds (`samm-c:lowerBoundDefinition`, `samm-c:upperBoundDefinition`):** Suggests `samm-c:AT_LEAST` and `samm-c:GREATER_THAN` for lower bounds, and `samm-c:AT_MOST` and `samm-c:LESS_THAN` for upper bounds.
* **Encodings (`samm:value` under `EncodingConstraint`):** Suggests standard character sets such as `samm:UTF-8`, `samm:US-ASCII`, `samm:ISO-8859-1`, `samm:UTF-16`, etc.
* **Characteristics (`samm:characteristic`, `samm-c:elementCharacteristic`, `samm-c:baseCharacteristic`, `samm-c:left`, `samm-c:right`):** Auto-completes predefined characteristics (`samm-c:Text`, `samm-c:Timestamp`, etc.) and all local characteristics defined in your files.
